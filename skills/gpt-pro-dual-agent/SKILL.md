# GPT Pro 双代理协作

先确定要交给 ChatGPT Pro 的问题、允许传出的材料，以及 Codex 最后要交付什么。用户要求外部评审，就交付经核对的评审意见；要求实现，才进入补丁流程。已有授权在本次范围内持续有效。

## 准备对话与输入

- 使用用户指定的浏览器、项目和对话；未指定时使用可用的浏览器工具。核对目标账号和套餐，保存完整对话链接。遇到登录、账号选择、CAPTCHA 或二次验证，让用户在界面完成，不索取凭据。
- 若依赖仓库，先读取相关仓库规则，记录分支、commit 和工作区状态。优先让 Pro 通过 GitHub connector 读出预期 commit 和一至两个可在本地核对的相关文件；图标或口头声称不能证明可访问。用户把 connector 列为前提时，无法验证就报告阻塞。
- 仅在获准上传对应内容时提供文件。不上传凭据、用户数据、浏览器状态或无关记录。需要回退到源码包时，只打包任务需要的基线文件；排除 `.git`、依赖、缓存和构建产物，做密钥扫描并检查可疑文件名，记录清单、字节数和 SHA-256。能在本地读取不代表可以外传。
- 默认以干净 commit 为协作基线。若确需未提交内容，只单独打包获准传输的 tracked diff 和明确获准的 untracked 文件，记录 `base_commit + local_overlay_sha256` 和清单，使外部交付与本地验收能还原同一基线。

## 委派与跟进

按 [任务说明模板](references/external-task-brief.md) 选用相关部分，写明事实来源、冻结决策、授权边界、产物和验收条件。外部贡献限于任务对话与已授权的附件交付，不得代做 commit、push、建 PR、部署、迁移或写生产数据；Codex 自己执行这些动作也须有对应授权。

| 用户要的结果 | 向 Pro 索取的产物 | Codex 如何验收 |
|---|---|---|
| 研究或评审 | 结论、可定位的原始来源或文件、尚不能确定的事项 | 回到来源核对影响结论的主张；不能复核的部分标为未验证 |
| 方案设计 | 推荐方向、取舍、被放弃的方案及对既有约束的影响；视觉设计附视觉证据 | 对照需求和已冻结决策，验证关键假设 |
| 代码实现 | 针对准确基线的补丁、仅含新增或修改文件的 ZIP、报告和 manifest | 按下方补丁流程在隔离 worktree 独立检查 |

同一交付物的纠错留在原对话；只为独立复杂任务另开对话。长任务保留原链接和进度；仍在推理或调用工具时继续等待。若只能观测页面，可每 2–3 分钟查看一次，连续三次且累计十分钟无变化时，再检查视口下方的回复、工具状态和连接。用原链接恢复，确认停滞后才从上次完成处续办，不重复派发或因耗时切换模型。

## 验收与纠错

收到补丁时读 [验收矩阵](references/verification-matrix.md)：保留附件原名，核对 manifest、大小和 SHA-256，先检查包内路径、软链接、权限及意外文件，再在隔离 worktree 还原准确基线、检查并应用补丁。逐文件对账 ZIP 与补丁涉及的新增或修改文件；生成物差异须有解释。审查变更范围、依赖和可执行内容后，才运行项目必需及与本次变更相关的检查。区分静态检查、模拟验证、实际运行和生产证据。

任何约定的必需项失败或无法验证，都不能报告验收通过。把具体位置、复现条件、预期和实测差异发回原对话，说明已通过部分；代码修正须针对同一基线回交完整产物，再检查受影响项。外部自报通过不能代替独立核验。若修正仍无进展、超出预算或依赖新的权限，保留已验收部分，说明阻塞和下一步。

将有价值的证据保存到仓库约定位置；无约定且允许本地写入时，可放在隔离工作区的 `.scratch/gpt-pro-dual-agent/<task-id>/`。不要把唯一副本留在临时目录或聊天里。交付时给出对话链接、实际产物、独立检查和剩余限制；涉及源码传输时列基线及包校验值，涉及代码时说明本地修改和实际远端状态。外部建议本身不改变已冻结的产品或契约。
