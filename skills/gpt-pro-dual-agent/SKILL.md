# GPT Pro 双代理协作

Codex 是最终负责人。ChatGPT Pro 是外部贡献者，其结论和代码必须由 Codex 在本地复现并独立验收。

## 建立协作契约

1. 提取用户目标、允许写入、禁止操作、证据要求和最终报告字段。
2. 委派前读取仓库约束和事实来源：
   - `AGENTS.md`、`CLAUDE.md`、`README`、构建清单以及相关架构或产品文档。
   - 当前分支、准确 commit、remote 关系和工作区状态。
3. 保护用户现有修改。原工作区较脏且可创建隔离 worktree 时，不直接在原工作区修改。
   - 默认以当前 HEAD 的干净 commit 作为外部协作和验收基线。
   - “允许读取脏工作区”不等于允许上传未提交内容。
   - 只有用户明确授权传输这些改动时，才将 dirty diff 作为单独、可审计的附件；不得把它静默混入源码包。
   - 若任务依赖未提交内容，将授权的 tracked diff 和明确授权的 untracked 文件组成 `local_overlay`，记录 `base_commit + local_overlay_sha256` 作为派生基线。外部 patch 必须针对该派生基线；验收时先在干净 `base_commit` 上复原 overlay，再应用外部 patch。
4. 严格限制权限：
   - 浏览器对话、源码打包、本地修改和测试需要用户明确授权或由任务直接隐含授权。
   - commit、push、PR、部署、数据迁移、生产配置和真实用户数据必须另行获得授权。
   - 经用户授权的任务对话和附件上传/下载属于协作传输，不属于这里禁止的运营写入；禁止项特指 SCM/PR/CI 配置、部署、迁移、生产配置和真实数据写入。
5. 遇到登录、账号选择、CAPTCHA、密码、Passkey、OTP 或 2FA 时暂停。不得索取凭据、Cookie、恢复码或 Token。

## 预检 ChatGPT Pro

当 `browser:control-in-app-browser` 可用时使用它，并遵循该 Skill 的确认和标签页清理规则。

发送正式任务前：

1. 确认预期 ChatGPT 账号和套餐已登录，但不暴露账号秘密。
2. 打开或复用目标项目中的对话。
3. 验证普通消息可以正常收发。
4. 如果任务要求 GitHub connector，让 ChatGPT Pro 读取：
   - 准确仓库。
   - 预期基线 commit。
   - 一至两个可在本地核对的任务相关 canary 文件。
5. 只有上述事实匹配时，才视为 GitHub 访问可用。连接图标或口头声称不足以证明。
6. 立即保存对话完整链接。

若 GitHub 访问不可用：

- 仅在用户授权文件上传时使用脱敏源码包。
- 不得假装 ChatGPT Pro 能读取本地文件或私有状态。
- 若 connector 是硬性前提，应报告阻塞，不能静默更换工作方式。

## 安全准备上下文

仓库源码优先通过 GitHub connector 提供。仅上传非仓库上下文，或在 connector 不可用时上传回退源码包。

准备源码包时：

1. 确认准确基线，以及是否需要包含用户已批准的本地修改。
2. 排除 `.git`、依赖目录、构建产物、缓存、数据库、运行状态、浏览器状态和无关大文件。
3. 排除 `.env*`、凭据、密钥、Token、Cookie、私有证书和用户数据。
4. 上传前执行密钥扫描，并人工检查可疑文件名。
5. 记录源码包路径、基线 commit、字节数和 SHA-256。
6. 保存足以证明实际传输范围的文件清单。
7. 如果包含 `local_overlay`，分别记录 tracked diff、授权的 untracked 文件清单和整体 SHA-256，确保派生基线可重建。

除非用户明确授权具体材料，不得上传 memory、浏览历史、终端历史、无关日志或个人文件。
读取仓库、截图或脏改动的权限都不自动包含向外部服务上传这些内容的权限。

## 有意识地拆分任务

每个相互独立的复杂任务使用单独的 ChatGPT Pro 对话；同一交付物的后续纠错保留在原对话。

当本地 subagent 可用且仓库约束允许时，使用范围明确的角色：

- `explorer`：只读梳理仓库和约束。
- `worker`：打包、隔离应用补丁或实现明确子任务。
- `reviewer`：独立审查正确性、回归、安全性和测试。
- `test_runner`：使用固定工具链验证，并按需补充聚焦测试。

Codex 不得委派总体责任。所有证据由 Codex 汇总，并由 Codex 决定是否验收。

## 发送可验收的任务说明

读取并实例化 [external-task-brief.md](references/external-task-brief.md)。

任务说明必须包含：

- 背景和目标。
- 准确仓库和基线。
- 事实来源和冻结决策。
- 允许修改的文件和行为。
- 禁止的变更和远端操作。
- 必须交付的产物。
- 必跑测试和环境限制。
- 可判定的接受与拒绝标准。
- 不得声称未执行验证的明确要求。

高风险任务中，要求 ChatGPT Pro 在实现前复述基线和边界。

## 监控但不干扰

1. 允许长时间推理和工具执行。不得仅因耗时较长就重复发送、打断或切换模型。
2. 默认每 2–3 分钟读取一次最新页面状态；页面仍显示推理或工具活动时不计为停滞。
3. 只要仍有进展就继续等待。
4. 至少连续三次检查、累计十分钟没有可见变化后，才进入停滞检查：
   - 完整回复是否在当前视口下方。
   - 工具是否暂停，页面是否存在可恢复状态。
   - 连接是否中断。
5. 使用保存的链接自主恢复；仅在确实停滞时，要求从最后完成的位置继续。
6. 不得让用户充当技术纠错的传话人。

## 接收产物，而非接受口头结论

优先要求针对准确基线提供完整交付：

- Unified diff 或 patch。
- 只包含新增和修改文件的 ZIP。
- 实现或研究报告。
- 列出文件名、字节数和 SHA-256 的 manifest。

默认 artifact contract：

- patch 使用可应用到准确基线的 UTF-8 unified diff。
- ZIP 以仓库相对路径为根，只包含新增和修改文件；不含绝对路径、父目录跳转或软链接。
- `manifest.json` 至少包含 `baseline_commit`、附件的 `path`、`bytes`、`sha256`、`purpose`，以及已执行命令和结果。
- 如果构建生成物导致 patch 应用结果与 ZIP 存在预期差异，必须逐项列出并解释；未解释的差异视为验收失败。

设计类任务不要求源码补丁，但必须提供决策理由、被拒方案、视觉证据和影响映射。

下载并保留附件原名，同时记录对话链接。附件可用时，不接受数千行粘贴文本作为可复现产物的替代。

## 独立验收

读取 [verification-matrix.md](references/verification-matrix.md)，选择所有适用检查。

至少完成：

1. 重新计算文件字节数和 SHA-256，并与 manifest 对账。
2. 检查文件类型、压缩包完整性、路径、软链接、可执行权限和意外文件。
3. 确认 patch 能应用到准确基线的干净副本。
4. 同时存在 patch 和 ZIP 时，逐文件比较 patch 涉及的新增/修改文件与 ZIP 内容。
5. 只在隔离 worktree 中应用，保护原工作区。
6. 审查范围、安全边界、依赖、锁文件、安装脚本和生成物。
7. 使用仓库固定工具链运行必需的 lint、格式化、类型检查、单元测试、合同测试、构建和相关 E2E。
8. Web 或浏览器原型使用用户指定浏览器；桌面应用使用实际目标 runtime。覆盖指定视口或窗口大小、操作系统和显示缩放、状态矩阵；在同一视觉输入中对比参考与实现，验证键盘、焦点、错误路径和当前 console/runtime 错误。
9. 明确区分 synthetic、mock、static、focused、actual runtime 和 production 证据。

ChatGPT Pro 声称测试通过，不构成本地验证证据。

任务说明中标为 required 的 gate 必须通过，才能验收；required gate 失败或因环境缺失而未验证时，状态只能是“未验收”或“外部阻塞”。optional gate 可以标为“未验证”，但必须披露剩余风险；若该风险改变交付结论，必须由用户明确接受。

## 推动纠错闭环

验证失败时：

1. 向 ChatGPT Pro 发送最小但完整的缺陷报告：
   - 严重级别。
   - 准确文件和行号。
   - 复现步骤。
   - 预期不变量。
   - 相关日志或截图。
2. 说明已经通过的部分，避免其重做或重新设计无关内容。
3. 可行时要求 RED-to-GREEN 覆盖。
4. 要求基于原始基线重新提供完整交付，避免含糊的手工片段。
5. 重新计算校验值、在隔离环境应用、重跑相关检查并安排独立审查。
6. 迭代至验收通过，或外部阻塞得到证实。

普通技术选项由 Codex 与 ChatGPT Pro 自主解决。只有登录认证、新权限、不安全的数据传输或重大产品方向需要升级给用户。

## 持久化证据并报告

将有价值的报告、manifest、截图、对比图、决策和验证结果保存到仓库既有证据目录。仓库没有约定且允许本地写入时，默认使用隔离工作区内的 `.scratch/gpt-pro-dual-agent/<task-id>/`；若原工作区只读或该目录不能持久保存，则使用其他经用户认可的持久位置。不得把唯一副本留在对话或系统临时目录。

不得因为原型或外部代理提出变化，就直接更新已冻结的产品、契约、架构或票据事实来源。先记录影响，再等待所需批准。

最终报告必须说明：

- ChatGPT Pro 对话链接。
- 仓库基线，以及使用源码包时的大小和 SHA-256。
- 实际本地修改。
- 要求 ChatGPT Pro 修正的问题。
- 独立测试和审查结果。
- 证据分类和剩余风险。
- 当前修改仅在本地，还是已经 commit、push、创建 PR 或部署。

如实说明失败和未验证内容。不得暗示实际未发生的远端或生产验证。
