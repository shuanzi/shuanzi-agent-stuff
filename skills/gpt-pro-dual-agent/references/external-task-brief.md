## 硬性边界

- 不新增产品范围，不重新打开冻结决策。
- 不修改 allowlist 之外的文件。
- 除非明确要求，不增加依赖或修改锁文件。
- 不 commit、push、创建 PR、修改远程 CI 配置、部署、迁移数据、修改生产配置或访问真实用户数据。经授权的本任务对话和附件交付不在此禁令内。

- 不声称执行过实际未运行的测试、浏览器验证、IPC、磁盘或生产验证。

## 必须交付

- 基于准确基线的完整 unified diff。
- 只包含新增或修改文件的 ZIP。
- 实现或研究报告，说明决策、修改文件、测试、未验证内容和风险。
- manifest，列出每个附件的文件名、字节数和 SHA-256。

默认格式：

- patch：可应用到准确基线的 UTF-8 unified diff。
- ZIP：以仓库相对路径为根，只包含新增和修改文件，不含绝对路径、父目录跳转或软链接。
- `manifest.json`：至少包含 `baseline_commit`、每个附件的 `path`、`bytes`、`sha256`、`purpose`，以及执行过的命令和结果。

设计类任务将 patch 和 ZIP 替换为：

- 最终备选方案或选定方向。
- 决策理由和被拒方案。
- 视觉证据。
- UI 变化与现有事实来源的映射。
