# 双代理协作验收矩阵

按任务风险选择适用项。未执行的检查必须在最终报告中标为“未验证”，不得静默省略。

## 1. 协作通道预检

- [ ] ChatGPT Pro 已登录，目标项目或对话可正常收发消息。
- [ ] 已保存每个对话的完整链接和任务归属。
- [ ] 若使用 GitHub connector，已让 ChatGPT Pro 报告准确 commit，并读取任务相关 canary 文件。
- [ ] 若 connector 不可用，已停止依赖它，并按授权准备脱敏源码包。
- [ ] 未向 ChatGPT Pro 提供密码、Cookie、Token、API Key、私钥或恢复码。

## 2. 源码与基线

- [ ] 已记录仓库路径、分支、HEAD commit、remote 和工作区脏状态。
- [ ] 已阅读仓库治理文件、README、manifest 和相关架构/产品文档。
- [ ] 已保护用户原有修改；验证工作使用隔离 worktree 或副本。
- [ ] 已明确外部协作基线；默认使用干净 HEAD commit，dirty diff 仅在单独获得上传授权后传输。
- [ ] 若任务依赖未提交内容，已用 `base_commit + local_overlay_sha256` 标识派生基线，并能在干净 worktree 复原 tracked diff 和授权的 untracked 文件。
- [ ] 源码包排除了 `.git`、依赖、构建物、缓存、数据库、运行状态、浏览器状态和凭据文件。
- [ ] 已对源码包做密钥扫描，并记录文件数、字节数和 SHA-256。

## 3. 外部任务说明

- [ ] 说明包含背景、目标、准确基线、source of truth 和当前架构。
- [ ] 说明列出允许修改的范围、不可破坏的边界和权限限制。
- [ ] 已明确允许的任务对话/附件传输，与禁止的 SCM、PR、CI、部署、迁移、生产配置或真实数据写入之间的边界。
- [ ] 说明列出明确交付物、必跑测试和可判定的验收标准。
- [ ] 复杂且相互独立的任务使用不同对话；同一缺陷的修正留在原对话。
- [ ] ChatGPT Pro 被明确禁止扩大范围、远端写入和把模拟验证声称为真实验证。

## 4. 交付物完整性

- [ ] 收到报告、补丁、仅含新增/修改文件的 ZIP 和 manifest；设计任务收到等价的决策稿和证据。
- [ ] 已记录每个附件的名称、字节数和 SHA-256。
- [ ] 压缩包能在隔离目录完整解压，无路径穿越、异常软链接或隐藏可执行文件。
- [ ] manifest 中的文件清单、基线 commit、测试结果与实际附件一致。
- [ ] patch、ZIP 根目录和 `manifest.json` 符合默认 artifact contract，或已书面约定等价格式。
- [ ] 补丁能干净应用到声明的准确基线。
- [ ] patch 涉及的新增/修改文件与 ZIP 逐文件一致；已解释生成物或允许差异。

## 5. 代码与供应链审查

- [ ] 修改只覆盖任务范围，没有顺手重构或静默产品决策。
- [ ] 新依赖确有必要，来源和版本合理，锁文件同步且无无关漂移。
- [ ] 已检查构建脚本、生命周期脚本、二进制、下载器和权限变化。
- [ ] 已检查信任边界、敏感数据、日志、文件系统、IPC、网络和恢复路径。
- [ ] 外部代理的假设已用本地源码或官方文档核对。

## 6. 独立验证

以仓库固定工具链运行适用门禁，并记录命令、退出码和关键输出。

- [ ] 格式化或 lint。
- [ ] 类型检查。
- [ ] 单元测试。
- [ ] 合同或集成测试。
- [ ] 生产构建。
- [ ] 相关 E2E。
- [ ] 若为 Web UI：真实浏览器主旅程、关键失败场景、窄窗口、键盘、焦点、控制台和减少动态效果。
- [ ] 若为桌面 UI：实际目标 runtime、操作系统、窗口大小、显示缩放、键盘、焦点和 runtime 日志。
- [ ] 测试环境与真实生产环境的差异已明确披露。
- [ ] 每项 gate 已标记 `required` 或 `optional`；required gate 均已通过。

required gate 失败或未验证时不得验收，只能标为“未验收”或“外部阻塞”。optional gate 未验证时必须披露剩余风险；若风险影响交付结论，需用户明确接受。

证据必须准确分类：

- `static`：源码、类型或配置检查。
- `mock`：使用模拟网关、fixture 或内存状态。
- `focused`：局部测试或目标回归。
- `actual runtime`：真实进程、浏览器或应用运行时。
- `production`：真实生产环境验证；未获得明确授权时不得执行或声称。

## 7. 缺陷修正闭环

- [ ] 每个反馈包含严重级别、文件/行号、复现步骤、期望约束和原始日志/截图。
- [ ] 修正请求要求最小完整改动以及更新后的全套交付物。
- [ ] 修正后先复现旧失败，再运行聚焦验证和受影响的完整门禁。
- [ ] 已确认旧附件不会与新版本混用。
- [ ] 无法解决的阻塞被定位到外部条件，而不是用模糊结论结束。

## 8. 持久化与最终报告

- [ ] 有价值的报告、决策、测试日志摘要和校验值已保存到持久位置。
- [ ] 证据使用仓库既有目录，或隔离工作区 `.scratch/gpt-pro-dual-agent/<task-id>/`，且不是唯一保存在系统临时目录。
- [ ] 冻结的产品或契约文档仅在用户确认后回写。
- [ ] 最终报告列出 ChatGPT Pro 对话链接。
- [ ] 最终报告列出源码基线、源码包大小和 SHA-256。
- [ ] 最终报告列出实际修改和要求 ChatGPT Pro 修正的问题。
- [ ] 最终报告区分通过、失败、未运行和未验证的检查。
- [ ] 最终报告列出剩余风险。
- [ ] 最终报告明确当前状态是仅本地修改，还是已提交、推送、建 PR 或部署。
