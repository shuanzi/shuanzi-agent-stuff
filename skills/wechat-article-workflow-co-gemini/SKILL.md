# 微信公众号文章协作

Codex 和用户讨论文章方向，负责搜集素材、独立核验事实并检查交付物。Antigravity CLI 使用 `gemini-4-argon-high`、`--effort high` 完成主笔、修订和 HTML 排版。

按[写作交接与核验](references/workflow.md)组织文章目录、记录进度和调用 CLI。进入修订排版前读取[公众号 HTML 交付](references/wechat-html.md)。续办时先回读进度、当前稿件和用户修改，已明确的决策直接沿用。

用户明确只要求润色、核验或排版时，只执行指定阶段和必要检查，不强行重走完整流程。

1. **构思。** 结合用户给的选题和材料，逐步收敛核心问题、读者、切入角度、观点、结构、篇幅及文风。形成写作简报，请用户确认方向后再开始素材搜集和主笔。用户已确认具体方向时直接进入相应阶段。
2. **搜集素材。** 整理用户给的文件与链接，结合公开检索补证，优先用原始论文、官方文档、原始数据或直接采访。记录出处、定位和能支持的主张。证据若动摇已确认的核心观点，带着证据返回讨论。
3. **委派主笔。** 给 Gemini 写作简报、素材包、交付路径和缺口记录要求。允许它组织论述和表达，包外关键事实由 Gemini 标记、Codex 补证。保留原初稿。CLI 失败时保留已有产物，报告实际原因和可恢复的进度，继续使用指定模型。
4. **核验并请用户审阅。** Codex 对初稿核对关键论断、数字、日期、人名、引语及归因，区分事实、观点和推断，形成具体修改清单。把初稿、核验结果和需用户决定的问题一起交回。收到用户对该稿的审阅结论或修改方向后再派发修订。用户直接改稿时，以其版本作为修订基线。
5. **委派修订和排版。** 将用户意见、核验清单及准确的基线交给 Gemini，优先用本篇的明确会话 ID 续写。交回配套的 Markdown、HTML 和修改说明。正文自然归因，文末列精选来源，完整核验记录另存。
6. **最终复核与交付。** Codex 逐项确认改动并核验新增事实，对照 Markdown 与 HTML 的内容，检查移动端预览和配图清单。常规纠错最多追加两轮 Gemini 调用，未解决的关键事实或方向冲突带回讨论。交付文章文件和实际验证状态，公众号内粘贴和手动上传图片分别记录。

交付范围到本地成稿文件及使用说明。发布标题在公众号标题栏填写，正文从浏览器复制，配图按位置清单手动上传。
