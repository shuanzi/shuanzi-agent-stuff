# 公众号 HTML 交付

修订阶段由 Gemini 负责视觉设计，Codex 回读和验证。文章主题、目标读者和已确认的文风决定强调色、标题样式、图注和间距。默认用适合手机阅读的单栏布局、清楚的标题层级、舒适的行距和段距。引用、重点和图表按内容需要设置。

## HTML 产物

- 交回和 Markdown 同版的完整 UTF-8 HTML 文档，含 `<meta charset="utf-8">` 和 viewport 元信息，浏览器可直接打开。Markdown 首个一级标题用作公众号标题栏标题，HTML 的 `<title>` 与其一致，浏览器页面主体供复制正文。
- 直接在正文元素使用 `style`。优先用 `section`、`h2`、`h3`、`p`、`strong`、`em`、`blockquote`、`ul`、`ol`、`li`、`a` 和 `img` 等基础结构。正文样式和阅读顺序在常用浏览器中应独立成立，避免脚本、事件处理属性、外部样式表、远程字体、嵌入式页面及交互组件。
- 配置能换行的段落和长链接，图像保持比例、宽度不超过正文。手机上过宽的表格用简短对照、分段列表或有同等信息的图示，转化时保留数据、单位、条件与注释。配图、引语和关键数字使用可读的字号与对比度。
- 正文保留自然归因，文末放精选来源，链接指向相应原始资料。核验表、修改指令、素材缺口标记和交付提示存放在独立文件。

## 配图和复制使用

只选能帮助说明文章的图片、截图或图表。默认从用户提供或使用条件明确的素材中选取，或用已核验的数据制作图表。图注要说明图像内容及必要来源，避免让示意图看起来像原始证据。生成图片或制作封面仅在本篇有相应要求时安排。

实际使用的图片文件放在文章目录的 `assets/`。本地 HTML 通过相对路径引用，配有替代文本和图注。`assets-index.md` 逐图记录文件名、正文插入位置、图注、来源、使用条件。尚未取得的图注明待办及其对文章的影响。

交付时提示用户在浏览器打开 HTML 并复制渲染后的正文，在公众号编辑器标题栏填写标题，按位置清单上传图片并核对图注。流程止于本地文件交付和使用说明。

## Codex 验收

1. 核对 Markdown 和 HTML 对应同一版文章。比较正文、段落顺序、标题、数字及单位、引语、图注、来源和链接。预览排版中的新增文案也纳入事实核验。检查标签、内联样式及引用路径，确认无缺图和泄漏进正文的内部备注。
2. 在浏览器用约 375 px 的窄视口预览，检查标题、首段、引用、段落行距、图片、长链接和表格，确认无横向溢出或文字截断。报告实际检查到的效果。不能打开浏览器时，记录已做的静态核对和未完成的预览。
3. 分别记录本地浏览器预览、公众号编辑器实际粘贴、配图实际上传。粘贴实测检查标题层级、段落、引用与强调，上传实测核对插入位置及图注。未在公众号测试时写明“本地预览已验证，公众号粘贴待验证”，其中本地预览状态按实际结果填写。
