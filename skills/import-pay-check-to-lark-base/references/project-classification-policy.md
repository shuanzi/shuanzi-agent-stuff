# 项目分类策略

只利用当前 Base snapshot 中已有、`项目` 非空的记录建立历史规则；不要引入外部分类模型、不要新增项目选项、不要覆盖已有非空项目。

## 优先级

1. 遇到精确重复且 `项目` 非空的记录时保持原值，不写入。
2. 遇到规范化交易对方、商品/备注和收支唯一对应同一现有项目时，返回 `high` 和该项目。
3. 遇到规范化交易对方和收支至少命中两条、且全部对应同一现有项目时，返回 `high` 和该项目。
4. 遇到单条弱匹配、多个项目、无历史、项目值不在 live options 中、项目字段为单选但有多个高置信标签、项目字段不存在或字段不可写时，返回 `low` 与空 `labels`。

规范化时只折叠空白、统一大小写和常见全半角；不要删除有意义的数字、日期或商户标识。

## 写入约束

- 高置信新记录在 `create_rows.fields` 中直接写入现有项目值。
- 低置信新记录以空 `labels` 生成 `项目: null`，继续写入备注、日期、金额、收支和责任人；不要将字符串 `pending` 写入 Base，也不要因此阻断其他字段或安全记录。
- 仅当精确重复记录的 `项目` 为空且分类高置信时，才按相同项目分组，用项目专属 patch 回填；不得触及同键中任何非空项目记录。
- 对 select/multiselect，先读取真实 options；候选项目不存在、单选无法承载多个标签或项目字段不存在时降为 `low`，绝不借写入创建选项，也不得因而阻断其他安全记录。
- 在确认后的第二个 snapshot 上重新计算分类；不要沿用确认前的 assignments。
