# 问答式差旅报销助手

用户说“帮我报销这次出差”即可开始。先读已有行程、票据、支付记录和任务底稿；信息足够时直接核算、填表和验收，缺项时再逐轮询问或接收补件，已有进度从缺项继续。办理整套报销的产物为组秘核验 ZIP 及包外核对记录；仅查规则或检查材料时直接交付所问条款、依据或缺件清单。

本包于 **2026-10-26 脱敏派生**，维护日期为 **2026-11-03**：保留规则、标准表和空白模板；历史实例、联系人、账户、截图及含联系人原始通知不随包复制。规则资料日期仍为 **2026-10-23**，未核验现行效力。日常使用直接查本地资料，无需联网或登录钉钉；在线地址只保留为来源记录。

## 按需读取

- 先读[离线资料索引](references/sources.md)，核对适用组织、维护日期和已知缺口。默认采用包内维护版本，不自动读取或刷新在线文档；只对缺失证据、原文冲突和适用范围未明确的事项保留“待核验”。
- 办理报销或接收补件时，读[问答与补传指引](references/intake.md)，将[信息采集表](assets/报销信息采集表.md)复制到本次任务的 `work/本次差旅信息.md` 并随材料更新。仅查询规则时直接回答对应问题。
- 国内差旅、会议培训、付款分配：读 [domestic.md](references/domestic.md)。
- 市内因公打车、出国境、R/T/GZ 项目：再读 [special-cases.md](references/special-cases.md) 相应部分。境外不套用国内补助、住宿和连续出差天数限制。
- 境外金额先查[地区索引与查询规则](references/overseas-rates-index.md)，按国家、城市及备注读取两份 CSV。总表 269 条、2017 住宿调整 61 条均已对照 PDF 逐行校订，保留记录 ID 与原页码；住宿、伙食、公杂费各自保留币种，不按国家直接合并覆盖。
- 实际填写 Word、命名及打包：读 [forms-and-files.md](references/forms-and-files.md)。
- 查规则条款时，按索引读取 `references/policies/` 中对应的脱敏规则文字；查附件字段或 PDF 页码时读 `references/attachments/`。两份费用标准 PDF 及通知检索稿按原页组织，表格支持稳定 ID 定位；发生原文疑点或范围冲突时回读对应原 PDF 页，不必一次加载全部原文。
- 维护规则或补充版本时，按索引末尾的维护约定更新本地正文、原始附件和清单；只有用户要求核对线上变化或重新同步时才访问来源。

## 工作方式

### 1. 逐轮收集事实和附件

先读用户消息、已有任务记录与附件，再决定下一轮问题。没有材料时，首轮询问谁出差、什么时候、从哪到哪、去做什么；随后补身份、部门与课题组及适用材料。每轮围绕一个主题，通常问 1–3 个相互关联的问题，不把整张采集表交给用户填写。至少区分：

- 出差人及身份、部门与课题组、经费类别、核算账号是否已由组秘确认。
- **申请覆盖起止日期、实际出差起止日期、填表日期**三个概念；目的地精确到省市区县；实际出差事由与课题任务。
- 普通交流或会议培训；逐日会议、供餐、交通安排，是否有“食宿自理”证明。
- 每笔订单的渠道、实际付款人、支付方式、已付金额、退款、手续费、改签费、是否已由公司/其他人报销或汇款。
- 每晚酒店所在地、人员标准、房间/同住人、入住离店、房费、发票和红章水单。

资料按人、行程、费用关联。使用 [费用与材料台账](assets/费用与材料台账.csv)，以序号关联每笔费用与附件，记录来源文件及页码/截图位置。收到一批便更新已确认项、具体缺件及人工待办，下轮只问尚缺信息。截图看不清、订单退款未闭合、所属行程冲突时，指出具体文件和疑点，取得补充证据后再纳入。

接收聊天附件或本地文件路径，保留原件并在任务目录操作副本。若只能看到聊天预览而拿不到文件字节，继续收集其他内容，明确请求原文件或本地路径，该附件仍列待补。人员、卡号、护照与实际票据仅保存在本次任务目录。

### 2. 按条件计算，保留可复核过程

使用十进制金额，先核对实际付款、退款及可报范围，再按人汇总。逐日处理补助；会议日不能机械乘 100/80；同一天实报交通费与交通补不得重复。火车票 5 元手续费只在凭证确实包含时拆出，12306 无手续费不减 5 元。

住宿按**地区、人员类别、实际住宿日期及淡旺季**查保留原 Sheet1 单元格值的 [住宿标准 CSV](references/lodging-sheet1.csv)。原始 XLS 不随脱敏包复制；标准疑点须取得授权原件后核对，不能凭本包推断。`Sheet3` 是“修改建议调查表”，不得作为标准。无法确定人员档次、区县或季节边界时保留待核验金额，不能选择最高标准。按夜列实际额、限额、可报额及超标自付额；核对同住票据没有重复申领。

输出计算明细：每个人的交通费、住宿费、杂费、伙食补、交通补、小计，另列付款方式分配及代付人。未确认金额留空或“待核验”，不当成 0，也不混入“已核验合计”。

用户明确确认本轮填表金额或付款分配口径时，可据此填写已确认字段，并在任务核对记录保留确认来源、适用范围及待后审事项；不把本轮口径升级为通用财务政策，也不将未知金额补成 0。

### 3. 填写原表并整理资料

优先用用户提供的当前模板，否则用附带原表副本。金额确认后，可用 `scripts/fill_domestic_form.py` 将已确认填写的国内数据写入原版 Word；它只校验、汇总和填表，不判断报销资格。字段与示例见 [填写说明](references/forms-and-files.md)。金额有缺口时先出字段草稿和缺项清单，不用脚本制造完整报销单。

地点、时间、合计只填原有空位，保留固定文字、字体、字号、下划线、段落及行高。付款备注放费用项下方对应格；备注占用原表下一费用行，容量不足时分表，不覆盖其他人员，也不靠改变样式挤入。

保留原件，操作副本；不伪造签字、不改票据交易事实。电子票据原文件保留，说明另附；需要在行程单添加出行人与事由时做标注副本。核算账号、财务复审和专项审核按原流程交相应人员填写/确认。

按用户指定位置输出；无指定时在当前任务建立 `原始材料/`、`work/`、`output/`。提交包目录只包含实际需要的报销材料，费用试算、缺项和内部核对记录放在包外。文件夹沿用出差申请标题中的**申请起止日期**，不是填表日期或提交申请当天；表内填实际行程。

### 4. 验收并交付

- 出差人应提供的关键电子材料必须齐备，费用、申请覆盖和付款归属须核清，报销表须回读后才生成组秘 ZIP。尚有缺件或金额、行程、付款归属冲突时，保存底稿并给简短补件清单，继续接收补传。
- 核算账号待组秘填写、线下签字、纸质原件交接、组秘后续同步/提交属于人工待办，单列负责人和动作。按渠道本应由出差人提供的推送记录等电子证明仍须补齐。签字说明需补电子扫描件的，按具体材料要求核对，不能一概转成人工待办。
- 费用项目之和＝人员小计之和＝报销合计＝公务卡＋银行卡＋公司汇款＋支票＋现金＋单位结算；无单位结算时按五栏相加。单位结算在相应费用项下备注，合计不新增该标签，也不冒充公司汇款；逐笔可追到原票据、支付与退款记录。代付、公司已付及单位结算金额不得重复打给出差人。
- 日期被有效申请覆盖，国内连续行程不满 7 天；延期不能只拆申请而继续累计满 7 天。境外另按外事流程。
- 按渠道和身份核对电子版、纸质原件、签字、水单、会议证明及电子票据推送状态。缺推送回执时只写“待推送/待确认”。
- 回读 Word 的姓名、日期、每列金额、合计和付款分配；有可用渲染器时检查分页、截断和签字位置。未做视觉检查如实标明。
- 依据[填写与打包说明](references/forms-and-files.md)生成 `work/组秘包清单.json`，用 `scripts/package_reimbursement.py` 按明确文件清单打包。脚本检查阻塞项、源文件、重名和已有输出，回读 ZIP 目录、数量及内容。解压后再核对报销单与附件关联。

材料未齐时，回复已收到什么、缺哪笔材料及下一步问题。齐备后给出 ZIP 的可点击路径、报销合计、文件数及仍需人工办理的事项，状态为“已整理，待组秘核验”，可附“待签字”。费用明细、材料核对与待办保存在包外，按需提供。用户只问规则或检查清单时按其范围回答，无需生成整套文件。

填写与整理不自动包含邮件、钉钉发送、ARP 提交、指定财务报销人、支付或票据删除。用户明确授权后才执行对应外部动作；已有具体授权无需重复询问。本包不保存联系人资料，执行前核对当前负责人和收件人。
