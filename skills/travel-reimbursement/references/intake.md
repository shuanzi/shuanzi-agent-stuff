# 问答与补传指引

用于从零办理报销、接收一批材料或继续补件。先读用户已给的信息和任务记录，再选择下一轮问题。信息采集表供 Agent 记录，不要求用户照表填写。

## 每轮的动作

1. 读取本次任务的 `work/本次差旅信息.md`、费用台账和新增附件，核对所属人员、申请和实际行程。首次办理时在用户指定位置建立任务目录，无指定位置时用当前任务目录，避免将不同差旅混在一起。
2. 从材料提取人员、日期、地点、金额、订单、渠道及支付事实。以台账序号作为费用关联编号，将发票、支付、退款等附件关联到同一笔费用。已有确认保留来源，用户修正或新证据冲突时更新受影响项。
3. 更新四种材料状态“已具备 / 待补 / 待核验 / 不适用”。缺失材料列待补，只有确认该场景无需此材料才能列不适用。另记核算账号、签字、纸质原件等人工待办。
4. 简短说明本轮收到了什么，再问下一组真正缺失的信息，通常 1–3 个相关问题。明确到人、行程段或酒店、费用日期及凭证类型。补齐后直接继续核对和生成，无须为每轮常规处理增加确认停点。

下一轮优先解决会改变行程归属、材料分支或金额的疑点。普通字段可从可靠材料确认，金额模糊、退款未扣、代付对象不明等须向用户追问。提问可以建议“直接发图、上传文件或给本地文件路径”。文字问答工具仅用于文字问题，附件请求通过普通回复表达。

收到截图先检查是否能读清交易对象、日期、金额、状态及订单标识。预订成功截图不能直接当付款成功证据。原 PDF 电子发票保留文件本体，付款截图与发票分别关联。仅在聊天中看过图片、未取得可打包文件时，记录识别结果并请求可访问的原文件，保持该附件待补。

## 从哪一轮开始

| 已有信息 | 下一步问题示例 |
|---|---|
| 只有“帮我报销这次出差” | “这次是谁出差？什么时候，从哪到哪，主要去做什么？” |
| 审批单和票据已能确定行程 | “已读到测试甲 10 月 20–22 日北京往返珠海。这次以什么身份出差，部门和课题组是什么？”只补材料未给的字段。 |
| 去回程、酒店已确定 | “去程和住宿已收到。还缺 22 日回程高铁的付款截图，请发这一笔。” |
| 两笔付款人不同 | “回程显示由测试乙付款。请确认这笔应回到谁、用什么方式回款，是否已有公司结算或退款？” |
| 补传了一批附件 | “本轮已补齐回程付款。现在还缺香洲区酒店的盖章水单扫描件。”只列最新缺件。 |
| 混入另一趟出差截图 | “这张付款图显示 9 月上海订单，与本次 10 月珠海行程不一致。请确认关联，或补本次订单的付款记录。” |

事实已从本轮资料核清时直接记入，不重复问上述示例。首轮可以问基本四项，之后按主题拆分，避免一次罗列所有特殊情况。

## 根据场景补问

国内规则详见 [domestic.md](domestic.md)，专项、市内交通和境外详见 [special-cases.md](special-cases.md)。以这些规则确定本次必需材料，下面用于选择提问主题。

- **人员和经费**。逐人确认所内、学生、劳务派遣、外协或专家身份，以及适用人员标准。多人同行确认是否同一核算账号，不同账号分别整理。完整账号可由组秘后填，仍须先弄清是否需要分表。只收集本次报销必需的个人资料。
- **申请和实际行程**。分别记录申请标题、覆盖起止及延期，实际出发返回、逐段起终点和活动。标题缺失时请求审批单或申请标题，不能用填表日或实际日期冒充申请覆盖日期。
- **交通和支付**。逐段确认预订渠道、订单、实际付款人、支付方式、付款状态、退款及回款对象。材料要求按渠道与身份分支确定，合并付款必须能关联到各笔费用，同一张截图可关联多笔但只打包一份。
- **住宿**。按晚确认酒店地区/区县、日期、房间和同住人、人员标准、实际费用，按渠道补付款、发票和水单。尚未确定区县、档次或适用限额时先保留待核验金额。
- **条件问题**。有会议培训时问通知、日程和实际供餐，申领伙食补时核对自理证明。出现退改签才收原订单、替代订单、退款及说明。出现接送站实报才核对当日交通补互斥。境外按外事资料、币种和汇率证据收集，避免套国内脚本。

## 持续记录与出包条件

将 [信息采集表](../assets/报销信息采集表.md) 复制为 `work/本次差旅信息.md`，每轮填写事实来源、已收附件、缺件、最近问题及人工待办。费用台账保留原文件与整理后文件映射。会话中断或用户补传时先读记录，沿用已有确认。新证据影响金额或清单时重新核对受影响部分，旧 ZIP 保留，重新生成用新的输出目录。

生成前检查以下条件。

- 申请覆盖和人员、行程一致，费用、退款、补助和回款对象已核清，报销表已生成并回读。
- 本次适用的关键电子材料均有可访问、清晰、正确关联的文件。存在缺件或上述事实冲突时，在 `work/组秘包清单.json` 的 `blockers` 逐项写明，只继续整理和补问，不能出组秘 ZIP。
- 核算账号待组秘填写、报销单线下签字、纸质原件交接和组秘后续办理单列人工待办。需要出差人提供的电子证明或签字扫描件仍按具体规则收齐，不因“待签字”三个字便全部跳过。

所有阻塞项由对应证据解决后，才将 `blockers` 更新为空列表，按 [forms-and-files.md](forms-and-files.md) 创建 ZIP。每个选入文件须对应本次实际要求，异地或历史行程截图先保留在工作记录中待核，不选入包。脚本执行文件清单检查，材料适用性和齐备性由 Agent 对照规则核验。
