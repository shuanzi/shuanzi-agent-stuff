# 模型服务 Benchmark

把实际服务配置、冻结的测试条件、逐请求证据和结论连起来。规范基线为[飞书《私有部署科研 Agent 模型推理服务 Benchmark 规范（修订建议稿 v2）》revision 85](https://my.feishu.cn/wiki/Tv7vwpewQi5JSskAiZdcIE3Wnxb)，规则见 [规范、矩阵与判级](references/spec-v2.md)。以该版本判断符合性；项目契约决定工具字段和可执行能力，不能以工具缺项免除核心验收要求。

用户只说“做一次 Benchmark”时，先从上下文确定阶段、目标和预算；仅在缺项实质影响成本、服务变更或结论时询问。不要默认跑完整 A–E，也不要把快速摸底称为规范验收。标为“〔本版建议〕”的规则在对应阶段默认采用并保留标注；调整须在运行前声明，记录偏离及受影响的结论，不能仍声称通过原口径。规范版本变化需明确差异后另行冻结，不静默替换本轮基线。

本技能评估生成式推理服务，不评估回答正确性、科研推理质量、Agent 工具调用或完整任务能力；Embedding／Reranker 不直接套用。

## 按当前请求选择范围

- **仅配置核查／先做方案**：只读服务与已有文件，交付能力、缺口和方案；不发送生成、tokenize 或预热请求。
- **执行测试**：先读 [规范、矩阵与判级](references/spec-v2.md)，再按 [A–E 执行阶段](references/stages.md) 冻结选定范围。区分摸底、容量判级与持续运行验收；已有授权内的常规配置和验证不增加审批停点。
- **仅汇总／出报告**：读 [指标口径](references/metrics.md)，用 [报告模板](assets/report-template.md) 复算已有证据，不连接服务或补跑请求。涉及 MVC／等级／阶段通过时按对应规范判定。
- **续测／停滞分析**：可用环境中的 `inference-service-benchmark` 恢复运行事实，但本技能的规范判据仍适用。旧轮仍在运行时接回观测，避免重复启动；新轮用新 run_id，记录父轮与差异，保留失败轮。

在个人工作区执行时读 [本地工具与能力差距](references/workspace.md)。需要追溯用户操作时读 [历史依据](references/history.md)；历史 18 点、单轮至少 30 请求、两小时上限只是摸底案例，不是规范采样要求，也不是 Stage E 长测。

## 1. 核查配置与观测

从当前会话、项目规则和实时证据建立事实；涉及仓库先检查分支和已有改动。

| 对象 | 核查内容与取证边界 |
|---|---|
| 身份与版本 | 主机／用户／目录、服务根 URL、后端版本／构建、模型 Revision、Tokenizer、模板、精度与量化；不能凭文件名认定已加载模型 |
| 实际服务 | 进程启动身份与命令行、监听、健康、模型接口；启动脚本与实际运行值分列 |
| 长度与并发 | 实际 ISL/OSL 和模板后长度是否适配单请求／slot 上下文；CPU 线程、slot、客户端并发、设备核数分别记录，请求并发也不等于团队人数 |
| 测量路径 | 控制端、服务端、客户端的位置，网关、流式缓冲和网络路径；客户端能力与限流不能被误当服务瓶颈 |
| 观测与资源 | 其他负载、进程范围、CPU／内存／Swap／设备资源，以及 Queue、OOM、重启、不可恢复错误证据；区分核心指标缺失与非核心硬件项不支持 |

完整环境字段、缓存和监控要求见 [规范参考](references/spec-v2.md)。保存带时间戳的快照和来源；认证只记录环境变量名。只有 HTTP 权限时，不承诺主机资源、硬件核数或 OOM 已核验。

测试已有服务不隐含安装、下载、重启、调线程、启用 metrics 或改权限。需要此类变更时，依据当前授权进入相应部署流程。健康检查通过不能替代生成与长度验证。

## 2. 冻结本轮约定

给出简短“步骤 → 验证”计划，保存规范版本、目标与阶段、目标等级（如有）、工作负载、到达方式、测试上限及必测／补充／可选清单。按 [采样规则](references/stages.md) 计算样本和预算；不承诺未知设备能在给定时间内完成。预算不足就缩小已声明范围或保留未完成状态，不能降低采样后声称原验收通过。

同时冻结数据／Trace 与摘要、seed、实际 token 长度、EOS／thinking／模板、缓存分组、生成参数；固定模型 Revision、Tokenizer、精度、量化和引擎参数。跨机器先明确同线程、满线程或各机调优口径。C 大于 slot 可以是排队实验，不等于物理核增加。

冻结逐请求 Goodput 目标与整点门槛、轮次、正式发压窗口、总时限、派发截止、单请求／空闲／无进展／排空时限及必要监控失败条件。规范默认单请求 300 s、流式空闲 60 s、无自动重试；长输出探索需更长时限时事先声明并独立分组。明确 tokenize、冒烟和预热的预算归属。

混合比例由当前任务明确并保存，规范未给出固定比例，不能自行补成“规范默认”。冻结新 run_id、未使用的输出目录、目标／方案哈希、实际执行源码／版本；各独立轮次可用独立 run_id 或工具支持的不可混淆轮次标识，修改条件使用新 run_id。

## 3. 执行、停止与恢复

核对工具能否提供所选阶段的调度、采样和证据，不能把增加请求数视为已有完整边界验收能力。能力不足时交付缺口与可执行范围，不擅自扩展为客户端开发任务；已授权的必要实现先用模拟服务验证 SSE、有效输出计时、token 计数、并发、取消和统计分母。

按冻结方案执行能力预检 → 有界功能／长度检查 → 每点至少 10 个且覆盖该点长度与并发的预热 → 正式阶段 → 排空。预热独立保存，不计正式统计；与 Prefix Cache 状态分开控制。后端字段、tokenizer 和计数需实际验证，不能拿字符数或另一 tokenizer 冒充等价负载。超时不是长度不支持的证据。

执行中保存请求阶段、实际在途数、客户端等待、目标／实际请求率和资源时序。进度说明当前阶段／点位／轮次、样本、最近有效输出、剩余预算和下一停点。

OOM、服务重启或不可恢复错误使该轮立即失败并安全停止；预算、健康、停滞或必要监控条件触发时，按约定停止派发、取消本轮客户端并记录原因。客户端退出不证明服务已排空；无法证明失败请求排空时结束本轮，不能把遗留负载带到下一点。

只管理本轮客户端和监控，不靠重启用户服务、延时、诊断重试或丢弃失败补成成功。恢复测试前核验进程、健康、代表性推理与监控已恢复；在已有授权内另开独立轮次，保留旧轮。Stage C 的复核／边界搜索及 Stage E 的降并发重测按事先冻结方案执行，均不能覆盖失败结果或突破授权预算。SSH 断开先恢复观测并核实远端任务，不重复发起。

## 4. 复算、判定与交付

按 [指标口径](references/metrics.md) 分开接口成功、长度有效性、轮次有效性和整点 PASS。按 [规范判级](references/spec-v2.md) 区分候选容量、完成边界复测的 MVC、测试上限下界和建议等级；A/B 通过不代表 C/E 或生产稳定性通过。

先取得终态与停止原因，回读健康、身份、活动请求和原始排空；之后空闲的回读另带时间戳。复核请求数、时间边界、实际并发、token、核心观测、配置与执行源码哈希。回收时核验文件清单及哈希；保留原始报告和实际执行源码，规范复算另写派生目录并注明版本。纯离线材料缺终态时列缺口，不连接服务补成历史证据。

使用 [报告模板](assets/report-template.md)，首页先给“配置与负载 → 已验证容量 → 该点吞吐 → 主要限制”，并列 Baseline 等级、Research／Heavy 容量和 Stage C/E 状态。每个配置 × 工作负载 × 并发／请求率 × 轮次保留一行，汇总中位数另列。

交付实际材料支持的逐请求 JSONL、CSV／JSON、配置／源码快照、日志、监控时序与图表；缺项明确记录，不补造。保留流程终态、证据审计、性能判定和服务终态四种结论，命令成功、哈希一致或审计通过不代表容量达标。成果脱敏，不保存凭据或敏感 Prompt；向飞书或聊天发布需当前任务明确授权。
